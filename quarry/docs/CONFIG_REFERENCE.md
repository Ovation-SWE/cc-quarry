# Configuration Reference

Set interactively via the master's `new` command (see
`docs/COMMANDS.md`); see `config/example.config.lua` for the resulting
structure with the same explanations inline. Validated by
`lib/validation.lua:validateConfig()` before any job can be deployed
(`validate` command, and automatically before `deploy`).

| Field | Type | Notes |
|---|---|---|
| `minX,maxX,minY,maxY,minZ,maxZ` | integer | Quarry bounds, inclusive. Any integers (negative, crossing zero) are supported. `min<=max` required on every axis. |
| `workerCount` | integer >= 1 | Requested worker count. If it exceeds registered workers, `deploy` refuses. If it exceeds the quarry's block volume, excess workers are left idle (reported by `partition`), never given a zero-volume job. |
| `fuelReserve` | integer >= 0 | Fuel that must always remain in the tank on top of whatever the current action needs, including the trip back to the unload point. See `dryrun`'s movement estimate before setting this. |
| `inventoryReturnThreshold` | number in (0,1] | Fraction of usable inventory slots occupied that triggers an automatic unload trip. |
| `liquidPolicy` | `STOP_AT_LIQUID` \| `BLOCK_LIQUID` \| `ALLOW_LIQUID` | See `docs/ARCHITECTURE.md`'s "Liquid handling". Lava is never passed through regardless of this setting. |
| `ignoredBlocks` | table of `[blockName]=true` | Blocks never broken, treated as obstacles. Use modern namespaced IDs (`minecraft:bedrock`), not legacy metadata values. |
| `unloadPoint` | `{x,y,z,direction}` | Where workers travel to unload/refuel. `direction` is `forward`\|`up`\|`down`, relative to the worker's facing on arrival. **`down` or `up` recommended**: `nav:moveTo()` doesn't guarantee a specific final facing (it only guarantees reaching the target coordinate), so `forward` only works reliably if you also control the approach direction (e.g. the storage is reachable from every plausible last-leg direction, or you accept occasional unload failures reported back to the master). |
| `depotPoint` | `{x,y,z,facing}` \| nil | **Optional.** A single shared staging-pad coordinate every worker can be placed at instead of its own exact `starting_position`. `facing` is the 0-3 cardinal convention (0=north); the depot chest must sit directly in front of the turtle at that facing (`turtle.suck()` only -- no up/down variant in v1). When set, a worker seeds dead reckoning at the depot, sucks fuel there (costs no fuel, so this works from an empty tank), then really travels to `starting_position` -- digging through anything in the way outside its partition. When unset (default), behavior is unchanged: the worker trusts it was placed exactly at `starting_position`. See `docs/SETUP.md`'s depot workflow and `docs/LIMITATIONS.md`. |
| `cleanupPass` | boolean | Reserved for a future second excavation pass to catch stragglers; see `docs/LIMITATIONS.md`. |
| `protocolVersion` | integer | Must equal `lib/protocol.lua`'s `protocol.VERSION` (currently 1). A mismatch is a configuration error the system refuses to silently work around. |

## Per-job fields (generated by `deploy`, not user-configured)

Every worker's `job_assign` payload additionally carries (see
`lib/validation.lua:validateJob()` for the exact shape enforced on the
receiving end):

- `protocol` -- must equal `"quarry.v1"`.
- `job_id` -- unique per quarry run (`master.lua`'s `newJobId()`).
- `worker_id` -- the specific computer ID this job is for; a worker
  rejects any job not addressed to its own `os.getComputerID()`.
- `quarry_min_x/max_x/...` -- the full quarry bounds (for reference/
  validation, not mined directly by this worker).
- `partition_min_x/max_x/...` -- this worker's hard mining limits.
  Never crossed during normal mining, even by falling-block handling.
- `starting_position` -- `{x,y,z}`, the top-of-partition corner the
  operator must place this worker at, facing north.
- `starting_facing` -- currently always `0` (north); see
  `docs/LIMITATIONS.md` for why this isn't yet operator-configurable
  per worker.
- `configuration` -- a copy of the quarry-wide fields above, plus
  `version` (= `protocolVersion`).
